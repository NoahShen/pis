## 1. 设计依据与边界

本规格将已批准的 D00 目标收敛为可测试的工程契约，不改动既有业务设计。权威依据：

- [技术实现设计 v1.0](../../PIS_技术实现设计_v1.0.md) §1.1～§1.2、§5.3：单进程、TypeScript strict、Node.js LTS、Fastify、Pino、独立 API Bearer。
- [任务拆分 v0.1](../../PIS_V1_开发实施计划与任务拆分_v0.1.md) §3「D00」：四张既有任务卡及 D00 Gate。
- [测试用例设计 v0.2](../../PIS_V1_测试用例设计_v0.2.md) §1.2、§5.2～§5.3.1：敏感日志边界、确定性验证及里程碑映射。
- [项目开发规范](../../project-development.md) §3～§7：固定技术栈、门禁与审核证据。

D00 仅提供构建工具链、测试设施和可启停的 HTTP 空服务。不连接数据库、不加载 Prompt、不请求外部服务、不创建业务队列，不实现业务 API、RSS 或 PM2 部署配置。后续模块按各自里程碑接入，不预建空服务层、容器或通用基类。

## 2. 运行时与工程契约

### 2.1 工具链

- 使用 Node.js LTS、npm、TypeScript `strict: true`，统一采用 ESM；TypeScript 使用 NodeNext 模块及解析规则，编译产物由 Node.js 直接运行。
- Lead 在 G3 前根据可用环境选择一个仍受支持的 Node.js LTS 精确版本及 npm 版本，记录选择依据；开发说明、版本约束与 CI 必须一致。不得仅凭本机已有版本推断其 LTS 状态。
- D00-T01 固化版本约束及 npm 锁文件；依赖安装使用 `npm ci` 复现。依赖更新必须带锁文件变更，不依赖全局 TypeScript 或测试运行器。
- 测试运行器选用 Vitest；格式工具选用 Prettier。具体兼容版本在 Plan/锁文件中落实，不作为新的业务或架构决策。
- 类型检查覆盖生产代码、测试代码和 TypeScript 工具配置；生产构建只输出运行所需代码，不包含测试、Fixture 或私密配置。构建前清理旧产物，避免已删除源码残留。
- 仅按任务引入所需依赖：Fastify/Pino 用于服务及日志，Zod 用于配置校验；better-sqlite3、node-cron 等留到对应里程碑。

### 2.2 命令契约

以下命令按任务逐步建立，尚未建立前不得宣称运行通过：

| 命令 | 行为与建立节点 |
|---|---|
| `npm ci` | 按锁文件安装，D00-T01 建立，D00-T04 干净环境验收 |
| `npm run typecheck` | 类型检查、不产生构建输出，D00-T01 建立 |
| `npm run build` | 清理并编译生产产物，D00-T01 建立 |
| `npm test` | 单次执行确定性测试，失败非零退出，不进入 watch，D00-T02 建立 |
| `npm start` | 启动已构建产物，不隐式安装或编译，D00-T03 建立 |
| `npm run smoke` | 验证编译后的真实进程启停及健康检查，D00-T03 建立；前置为 build |
| `npm run format:check` / `npm run format` | 检查/修复授权工程文件的格式，D00-T04 建立 |

格式工具不得批量重写权威设计文档、通用规范或 Prompt 原文。具体文件边界由 Plan 明确。

## 3. 确定性测试设施

### 3.1 Clock 与 ID

- 最小 `Clock` 契约为 `now(): Date`，返回一个时间点；生产实现使用系统时钟，测试实现允许设置固定时间并显式推进。调用者修改返回的 Date 不得改变 fake clock 的内部状态。
- 最小 `IdGenerator` 契约为 `next(): string`；生产实现使用 Node.js `crypto.randomUUID()`，测试实现返回预置的确定性序列，序列耗尽明确失败，不回退到随机值。
- 用依赖参数注入这两个接口，避免全局可变单例和依赖注入框架。D00 不决定未来各业务表的 ID 约束。
- 统一时间格式函数将有效 Date 输出为 `YYYY-MM-DDTHH:mm:ss.SSS+08:00`，表示同一时间点；无效 Date 明确抛错。UTC 跨日、跨月等转换正确且不依赖进程 `TZ`。该格式适用于应用时间输出，不要求更改 Pino 默认时间戳。

### 3.2 Fixture 与资源隔离

- Fixture 使用最小合成数据，测试不需要真实 Token、LLM、RSS、数据库或用户私密内容。
- 每个需要磁盘的测试创建独立临时目录，并在成功/失败后清理自己创建的资源；不得清理共享项目目录。
- 测试可并行或重复运行，不共享固定端口、可变 Clock/ID 状态和可写 Fixture。
- HTTP 组件验证优先使用 Fastify injection；进程 smoke 使用 loopback 及操作系统分配的临时端口，真实验证编译产物和信号处理。

## 4. 配置与 HTTP 契约

### 4.1 配置输入

从入口读取环境变量，转为经过校验的配置后传给应用；导入模块不读取配置、不监听端口、不注册进程信号。无需引入自动读取 `.env` 的依赖，开发说明给出 shell 设置示例。

| 输入 | 默认值 | 约束 |
|---|---|---|
| `HOST` | `127.0.0.1` | 非空且无首尾空白；不可绑定的地址在启动阶段报错 |
| `PORT` | `3000` | 十进制整数字符串，范围 0～65535；0 供测试/本地临时端口使用，记录实际监听端口 |
| `API_TOKEN` | 无 | 必填、非空、不得含空白；无开发默认 Token，不把原值写入错误信息 |
| `LOG_LEVEL` | `info` | `fatal/error/warn/info/debug/trace/silent` 之一 |

仅未设置的可选变量使用默认值，显式空字符串视为无效。未知环境变量忽略，以兼容系统环境。配置校验失败时不监听端口，输出不含配置值的错误字段及原因，进程非零退出。

### 4.2 健康检查与鉴权

D00 只注册 `GET /health`。为了沿用单用户 HTTP Bearer 边界，不提供匿名健康检查例外。

| 请求 | 响应 |
|---|---|
| `GET /health`，有效 Bearer | HTTP 200，JSON `{"status":"ok"}` |
| `GET /health`，缺失、错误或格式非法的 Authorization | HTTP 401，JSON `{"error":"unauthorized"}`，`WWW-Authenticate: Bearer` |
| 未注册路径 | HTTP 404，沿用 Fastify 默认行为，不产生业务副作用 |

- Authorization 仅接受一个 `Bearer <token>` 凭据；scheme 不区分大小写，Token 大小写敏感且精确匹配，拒绝空 Token、额外字段及重复 Authorization。用安全比较方式比对，长度不同也按未授权处理。
- 健康响应只表示 HTTP 空服务可用，不宣称数据库、LLM、队列或 RSS 已就绪；不返回环境、版本、Token 或配置。
- 此处的路径及错误响应仅约束 D00 健康接口，不提前规定 D03/D14 的业务 API 错误码、分页或路由。
- `/api/*`、`/feeds/*` 在 D00 均未实现；不得为测试添加公开调试接口。

### 4.3 应用装配边界

应用工厂接收已校验的配置及必要测试依赖，返回可注入请求、可监听、可关闭的 Fastify 实例。工厂与进程入口分离，允许多实例测试而无模块导入副作用。函数名及实际模块路径由 Lead 在 Plan 固定。

## 5. 生命周期、错误与日志

### 5.1 启动和关闭

1. 入口校验配置、构建应用、注册必要的 SIGINT/SIGTERM 处理，然后监听。
2. 监听成功后记录实际监听地址/端口及就绪事件；端口占用等监听失败必须非零退出，不能记录虚假的就绪状态。
3. SIGINT 或 SIGTERM 触发关闭，调用 Fastify close 停止接收新连接并等待当前请求；重复信号复用同一关闭过程，不重复释放资源。
4. 正常关闭完成后退出码为 0，释放监听资源和本阶段创建的定时器/信号监听器。关闭失败退出码非零。
5. 进程关闭设置 5 秒上限；超时记录安全错误并非零退出，避免无限挂起。正常路径不得用立即 `process.exit()` 截断待完成请求或日志。

该关闭契约仅覆盖 D00 HTTP 服务；六阶段排空、内部派发、任务取消及 PM2 守护由 D15 实现。

### 5.2 日志安全边界

- 使用 Pino 结构化日志，记录就绪、关闭和必要错误；HTTP 日志只保留请求 ID、方法、无查询参数的路径、状态码和耗时等必要元数据。
- 不序列化完整环境变量、配置对象、请求/响应 body、Authorization、Cookie、Prompt、完整 RSS 秘密 URL 或正文。Header 敏感字段配置脱敏；脱敏不能代替最小字段选择。
- 异常日志按允许字段输出，禁止无筛选地写入可能含输入原值的校验错误对象。未授权响应不得区分 Token 不存在与不匹配。
- 验收通过捕获日志验证敏感标记未出现，不能只检查代码里是否配置了 redact。

## 7. 集成与交付契约

- 干净 checkout 在指定环境下依次执行 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`、`npm run smoke`、`npm run format:check`。全部退出码为 0 才满足工程验证出口。
- CI 采用 GitHub Actions，在 PR 和主分支变更时执行上述验证；Node/npm 版本与本地基线一致。测试 Token 仅使用进程内生成的测试值，无需生产 secrets 或外部服务。
- README 记录先决版本、安装/验证命令、配置变量、启动/关闭方法、健康请求示例、当前范围及后续未决项；不得包含真实 Token。
- Git 忽略依赖目录、构建产物、测试临时产物、日志、数据库、私密环境配置及 `.DS_Store`。纳入锁文件和可复现的工程配置。
- 四张任务逐项保存测试证据、Lead 审核和 Architect 复核；里程碑末另做干净环境集成验证。远程 CI 尚未运行时明确记录 NOT_RUN，不以本地通过替代远程执行事实。
