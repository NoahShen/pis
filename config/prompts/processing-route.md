# Content Routing (P-01)

## 任务

判断当前 Content 应当进入哪些后续分析流程：

- `EVENT`：可能包含值得识别、记录或更新的现实事件事实。
- `KNOWLEDGE`：可能包含值得学习、理解、借鉴或使用的知识内容。

可以选择一个、两个或都不选择。此处只做宽松初筛，不负责最终事实增量或个人知识价值判断。

## EVENT 路由规则

当内容包含可识别的现实事件、状态变化或新的事实进展时，选择 `EVENT`。例如：

- 公司发布新产品、技术或正式公告。
- 监管部门公布政策或决定。
- 企业发生经营、组织或业务变化。
- 科研项目取得可识别的新进展。
- 某项持续性事务出现新的客观变化。

不在此阶段判断 Event 是否已存在或报道是否重复，这属于 Event Analysis。
纯观点、一般知识介绍、没有实际发生的预测，不应仅因此选择 `EVENT`。

### 不构成 EVENT 推广与自述样本

以下内容即使描述了某种“正在发生”的动作，也不选择 `EVENT`（也不因此选择 `KNOWLEDGE`）：

- 营销推广、付费课程或社群招生、限时优惠与报名引导。
- 无可核实主体、时间或客观结果的个人宣传与能力展示。
- 仅罗列自身成果或服务、不形成可追踪客观状态变化的内容。

若同文附带了独立、可核实的客观事实进展，仅按该事实部分判定。

## KNOWLEDGE 路由规则

当内容可能包含值得理解、学习、借鉴或使用的信息时，选择 `KNOWLEDGE`。例如：

- 深度分析、新观点或值得思考的解释框架。
- 方法论、技术实践和研究论文。
- 真实经验、失败教训和复盘。
- 具体而有用的工具、软件、资源介绍。

不在此阶段判定其对特定用户是否真正有价值，最终由 Knowledge Analysis 判断。

## 路由原则

1. `EVENT` 与 `KNOWLEDGE` 可以同时选择。
2. 不使用用户背景或 Topic 列表做筛选。
3. 不检索历史 Event / Knowledge，不判断重复或增量。
4. 仅依据本次提供的 Content；对于 `PARTIAL` Content，不填补缺失事实。
5. 有可信迹象但暂不能确认时，优先交给下游分析模块，避免过早遗漏；但第「不构成 EVENT」一节列出的推广与自述样本不属于可疑迹象，应直接排除。
6. 明显不包含事件事实或知识内容时，返回空数组。
7. 不调用外部工具，不产生数据库 ID，不评价重要程度。

## 输出要求

严格按照调用方提供的输出 Schema 返回 JSON，且只输出合法结构。
唯一业务字段为 `routes`：元素仅允许 `EVENT`、`KNOWLEDGE`，不重复；也可为空数组。
不输出解释、评分、置信度或其他字段。
